# Тесты

Дерево повторяет `src/`, файл в файл. Тест для `src/lib/server/catalog.ts` лежит в `tests/lib/server/catalog.test.ts` — путь к тесту читается как путь к модулю, который он проверяет, и искать ничего не нужно.

```
tests/
├── lib/
│   ├── bot/         правила бота: переходы статусов, текст карточки
│   ├── components/  компоненты (jsdom + @testing-library/svelte)
│   ├── server/      серверная логика: каталог, корзина, заказы, бот
│   └── *.test.ts    чистые модули: деньги, поиск, склонения, схемы
├── routes/          границы «браузер → сервер»: form actions и вебхук
└── setup/           общая обвязка прогона
```

## Как запускать

```bash
npm test              # весь набор один раз
npm run test:watch    # то же в watch-режиме
npx vitest run tests/lib/server/catalog.test.ts   # один файл
```

## Два прогона

Настроены в `vite.config.ts` как отдельные проекты vitest:

| Проект   | Где идёт | Что берёт                     |
| -------- | -------- | ----------------------------- |
| `server` | node     | всё, кроме `*.svelte.test.ts` |
| `client` | jsdom    | только `*.svelte.test.ts`     |

Отсюда правило именования: **тест компонента обязан называться `*.svelte.test.ts`**, иначе он попадёт в серверный прогон и упадёт на первом же обращении к DOM.

`setup/client.ts` подключается только к клиентскому прогону: матчеры jest-dom и заглушки того, чего нет в jsdom (`matchMedia`, `IntersectionObserver`, Web Animations API). `setup/matchers.d.ts` — те же матчеры, но для TypeScript.

## Как писать

**База не поднимается.** Prisma мокается через `vi.mock('$lib/server/db', …)`, так что тесты не ходят в Neon и не требуют `.env`. Если тест начал требовать базу — что-то пошло не так.

**Импорты через алиасы**, не через `../../../src`: `$lib/...` для библиотеки, `$routes/...` для роутов (алиас задан в `svelte.config.js`). Путь мока должен совпадать с тем модулем, который импортирует проверяемый код, — vitest сопоставляет их по итоговому файлу, поэтому `$lib/server/db` перехватывает и `./db.js` внутри `catalog.ts`.

**Название теста — это утверждение о поведении**, а не о реализации: «розмір без залишку вибрати не можна», а не «повертає false». Когда тест падает, его название должно объяснять, что сломалось у покупателя.

Комментарии — украинские, как и везде в коде; этот файл и остальная документация — русские.
